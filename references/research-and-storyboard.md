# Research and storyboarding

Read this when planning the deck or looking for project photos and product references.

## From documents to slides

1. Record the audience, setting, purpose, and any hard constraints such as an exact page count, title, name, or class. Use the latest user correction for the affected field. Keep source files intact unless the user requests changes to them.
2. Give each slide a sentence the speaker can say. A practical order is context, key problem, cause, what each party did, evidence, and next steps. Map factual and numerical claims to a source. Flag unresolved conflicts and preserve their scope. For instance, a vendor-announced outcome, a project's target, and a team proposal each need a different visible label.
3. Allocate space by narrative weight. If the user asks to expand 12 pages to 20, give the new pages distinct questions to answer. Add mechanisms, a worked example, actor responsibilities, outcome versus target, and criteria for the next decision. Keep expansion within the source evidence.
4. Use presenter notes for detail that would crowd a projected slide. Keep amounts, units, and dates consistent between the visible slide and the notes. Prefer a single editable deck to extra files when that is the agreed deliverable.

## Find and verify real images

- Start with an official project page, event gallery, product documentation, or an identified photographer or publisher. Search with the entity name plus terms for the specific subject. Examples include workshop, deployment, control room, launch event, and product screenshot.
- Open the parent page. Find the image in the actual article or relevant gallery, and read its caption or surrounding text. A related-story thumbnail can depict a different company. Check the subject, time, and place before treating an image as evidence.
- Use a product screenshot to explain a general capability only when it is labeled as an example. Treat image search thumbnails as discovery and retrieve the approved original from its source. Inspect the crop at slide size and preserve important details such as captions, visible labels and people.
- Record the creator and rights or terms for the intended use. A public website and a visible credit do not automatically grant redistribution rights. For a public deck or repository, use your own work, a compatible license, or permission. Preserve existing credits and the license terms. Keep unapproved examples, attachment screenshots, private data, and source documents outside a public repository.
- Save embeds locally when the deck must present offline. Keep original or traceable source files and normalize formats only as needed for reliable playback. If one image or a video cannot be used, prefer a sourced still and a short explanation over an unfamiliar online player.

Use any compact source ledger that the exporter or team actually consumes. Useful fields include:

| Field | Why it matters |
| --- | --- |
| Claim ID or asset filename | Ties evidence to a slide or native object |
| Source page and asset URL | Provides context and the original media location |
| Creator or publisher, terms, date | Supports credits and redistribution decisions |
| Verified subject and placement | Prevents mislabeling and helps check the crop |
| Status | Distinguishes sourced, unavailable, and proposed materials |

## Visual patterns

| Slide job | Useful pattern |
| --- | --- |
| Cover or chapter opening | Photo that establishes the subject, a dark or light gradient scrim, a short editable headline and a readable credit |
| Shift from real world to solution | Two photos in the same frame, a stationary scrim and an incoming image fade synchronized with a new headline |
| Evidence or budget | Calm background, one figure or real chart as the focal point, readable labels and sources |
| Explanation | Process, comparison, or diagram first. Use one inset photo or a diagnostic view only if it clarifies the explanation |
| Closing | Repeat a meaningful visual motif, state the next action, and make references reachable |

Treat layouts and animation timings as design choices. Use photography where it adds context, and leave data-heavy slides visually quiet when it improves readability.
