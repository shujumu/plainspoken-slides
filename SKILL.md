# Plainspoken Slides · 最直白的汇报PPT

Build an editable briefing that a presenter can explain one claim at a time. Use real, attributable images to orient the audience, then cue the story with restrained native PowerPoint motion.

1. **Establish the brief.** Read the supplied materials and the latest user corrections first. Identify who will see the deck, what they should understand or decide, the page count or speaking time, and the expected playback environment. Honor explicit facts, file formats, and language. Ask only when unresolved information changes the result.
2. **Plan the argument.** Make a slide-by-slide list of takeaways, evidence, and a visual job for each slide. Start with the question or recommendation, explain what happened and who did what, then show results and next steps. Keep measured outcomes, estimates, and future targets labeled. For revisions, start from the best source deck and preserve accepted content while updating affected pages, notes, and sources.
3. **Research and select images.** When the user requests web research and the host has access, search for the named project, location, product, or event in authoritative sources. Verify a photo against its own article, caption, and visual content. Label general industry or product illustrations as such. Record the source page, creator, usage terms, and slide placement. Embed approved image files when offline playback matters. Use the user's supplied materials or an honest text/diagram fallback if web access is unavailable. Read [Research and storyboarding](references/research-and-storyboard.md) for the source ledger and slide patterns.
4. **Build the editable deck.** Prefer native text and shapes and use a real chart when the data needs later editing. Alternate photo-led covers, chapter breaks, and conclusions with quiet, readable evidence pages. Use a gradient scrim over a photo when text needs contrast. Use a stable backdrop, an incoming picture in the same frame, and a separate headline for a true same-slide image crossfade. Read [Photo motion and export](references/photo-motion-and-export.md) before implementing it. Use the requested exporter. If none was selected, use an available native PPTX workflow such as PPT Master.
5. **Verify the delivered file.** Inspect the rendered pages for crops, contrast, clipping, and wrong credits. Confirm that the exported file has the planned slide count, notes and editable objects where requested, embedded images, and the intended motion targets. Use the bundled checker for package evidence, then play or render a representative moving slide in the intended player when possible. State precisely what was tested and any playback limitations.

For a full start-to-finish example brief, see the [Chinese README](README.md) or [English README](README.en.md). The optional checker runs locally with no network access.
